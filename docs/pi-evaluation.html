面试讲解稿
我把客服 Agent 的评测做成规则优先的离线闭环。先定义意图、必要信息、工具与 Skill 以及会话目标；运行真实 Pi 链路并立即保存 Trace。硬条件通过后，再用四维 Judge 评估答案。多轮看最终任务是否达成，重复运行看全部运行成功率。失败按证据聚成问题簇，修复后重跑相同场景，并在配置一致时对比基线。
为什么还需要规则？
模型可能偏好流畅回答。漏调工具、参数错误、无依据的退款完成声明，应在 Judge 之前确定性拦截。
怎么发现根因？
用 request_id 串起输入、路由、工具与 Skill；findings 给候选模块和行动项，根因仍需证据复核。
如何避免记忆串场？
run / case / repeat 生成独立身份，同一会话各轮保持身份一致；真实测评仍需独立基础设施。
怎样对待高分？
先核对样本和评分器。现有候选集未业务复核；Judge 需独立模型与人工校准，存档指标不能直接外推线上。
