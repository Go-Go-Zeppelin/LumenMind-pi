讲清楚链路，也讲清楚边界。

    
基于当前 LumenMind-pi 源码制作。订单场景引用 2026-10-08 验收记录；其余场景是可复述的流程示意。

    

      
① 先讲服务边界
TypeScript + Pi 负责会话编排、意图路由、Agent 工具循环与 Composer。Python FastAPI 负责记忆、知识库、SQLite 查询、评测与监控。旧 :8000/chat 代理到 Pi，原生入口为 :3000/chat。

      
② 再讲数据怎样变
ChatRequest → MemoryContext → IntentDecision → RoutingDecision → AgentRunInput → AgentRunResult[] → ChatResponse。
意图识别与主辅路由是两次决策；多个目标由 Promise.all 并行执行。

      
③ 让工具结果成为回答依据
模型决定是否调用工具。知识检索走 Python / ChromaDB；订单账单查询走 Python / SQLite；错误码等角色工具在 TypeScript 本地执行。业务工具用闭包绑定本次 userId，工具参数不暴露用户身份。

      
④ 最后讲容错与可观测性
记忆读取失败返回空上下文；写入失败保留本轮回答。专业 Agent 异常回退 General；Composer 异常确定性拼接。request_id 关联工具输入、输出与错误；Trace 默认仅存进程内最近 200 条。

    

    

      
编排、会话锁、澄清、路由、写回、Traceagent-service/src/agents/orchestrator.ts · chat / runChat / runWithFallback
