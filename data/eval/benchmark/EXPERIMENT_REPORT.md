# LumenMind-pi 可复现实验报告

实验日期：2026-09-07  
Agent 模型：`deepseek-v4-flash`  
意图链路：规则高置信度直出；否则 Embedding 候选召回后由 LLM 裁决  
知识库：当前内置 6 篇文档  
查询改写：关闭（`KNOWLEDGE_QUERY_REWRITE=false`）

## 数据集声明

- 意图集：500 条固定随机种子生成的模板化合成样本，共 19 类，每类 26–27 条。
- RAG 检索集：60 条基于当前 6 篇默认知识文档整理的问题，每题标注 1 个相关文档标题。
- RAG 答案集：30 条，每题包含参考答案和必须覆盖的事实。
- 500 条意图数据没有经过人工逐条复核，不能称为“人工金标”或“生产 Benchmark”。本实验主要用于建立可复现基线和发现系统问题。

## RAG 检索结果

因为每道检索题只标注一个相关文档，本实验中的 Hit@K 与 Recall@K 数值相同。

| K | Hit@K | Recall@K |
|---:|---:|---:|
| 1 | 55.00% | 55.00% |
| 3 | 88.33% | 88.33% |
| 5 | 100.00% | 100.00% |

这只能说明当前 6 篇小型知识库上的标题命中情况，不能外推到百万级知识库。Top-1 偏低表明当前默认 Embedding 对中文细粒度排序不够稳定；Top-5 达到 100% 也受到知识库总共只有 6 篇文档的显著影响。

## RAG 答案结果

| 指标 | 结果 |
|---|---:|
| 问题数 | 30 |
| 必须事实覆盖率 | 90.00% |
| `knowledge_search` 实际使用率 | 96.67% |
| 答案集意图准确率 | 86.67% |
| Judge 通过率（重试后） | 100.00% |
| 严格联合通过率 | 83.33% |
| Judge 平均 overall | 0.9958 |
| 最终 Judge 技术失败 | 0 |

严格联合通过要求：必须事实覆盖、Judge 达标、业务规则检查通过。

需要谨慎解释以上结果：

1. Judge 与被测 Agent 使用同一模型供应链，且评分接近饱和，存在明显的自评偏差风险，不能把 0.9958 当成人工认可率。
2. 首轮 Judge 出现过空 JSON；加入最多 3 轮的失败样本重试后，技术失败降为 0。
3. 两个回答在安全语境中明确说“绝不会索取密码/验证码”，仍被当前敏感词正则判为违规，属于规则误报。
4. 两个事实检查属于同义表达误判：`清除应用缓存` vs `清除缓存`、`身份验证失败` vs `认证失败`。
5. “持续 500”回答未覆盖参考答案中的“稍后重试”，属于真实的必含事实缺失。

因此，83.33% 是当前未校准评测器下的原始严格通过率；在修改正则或事实标签前，不应手工把它调整成更高的正式指标。

## 结论

本次实验没有复现材料中的 91.3% / 0.89 / 88.7% / 91.2%。当前可复现结果是：

- 合成意图集 Accuracy：85.00%。
- 合成意图集 Macro-F1：0.8492。
- 小型 RAG 集 Hit@3：88.33%，Hit@5：100.00%。
- RAG 必须事实覆盖率：90.00%。
- 未校准严格答案通过率：83.33%。

正式对外使用前，应优先补充独立人工金标、真实流量分布样本、检索 chunk ID 标注、不同 Judge 模型和人工一致性校准。

## 复现

生成数据：

```bash
.venv/bin/python python-service/evaluation/benchmark_suite.py generate
```

在 Python 基础设施和当前 Pi 服务启动后运行全部实验：

```bash
.venv/bin/python python-service/evaluation/benchmark_suite.py run \
  --pi-url http://127.0.0.1:3100 \
  --python-url http://127.0.0.1:8100 \
  --concurrency 6
```

也可以分别运行 `intent`、`retrieval` 或 `answers` 子命令。
