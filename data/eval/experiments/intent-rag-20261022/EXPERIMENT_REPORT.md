# 意图分类与 RAG 检索优化实验

2026-10-22。优化代码已实现，测评使用本地隔离服务 `127.0.0.1:3100/8100`，没有调用现有部署的 `/chat`、业务写入或记忆接口。

## 结果与口径

固定现有 500 条、19 类合成意图样本和 `rag_retrieval_v2.jsonl` 的 120 条检索题；后者包含 43 道多标签题、12 篇默认知识文档。没有修改问题、相关标题或评分阈值。模型均为 `deepseek-v4-flash`，分类温度为 0，Embedding 仍为 Chroma 默认的 `all-MiniLM-L6-v2`。查询改写与 LLM 检索重排均未使用。

意图“优化前”是本次重新运行的结果，并非用户提供的历史分数。历史存档为 Accuracy 85%、Macro-F1 0.8492，本次旧代码重跑得到 88%、0.8801，说明模型服务行为与运行时间可能影响结果。旧报告的 60 题、6 篇文档口径不能与当前 120 题、12 篇文档混用。

## 修改与消融

1. **分类边界规则**：显式区分经理/主管升级与普通人工接手；补充付款失败、扣款与订单状态不一致等关系表达；“扣费”回归一般账单规则，只有异常证据才进入支付异常。处理否定的人工请求，保留原始消息供实体提取。通用办理请求必须有操作及对象，礼貌性的“帮我看看”不再直接决定类别。保留技术与支付复合问题原有的主辅 Agent 优先级。
2. **分类提示词**：说明完整 19 类定义，先判断业务领域，再判断通用查询/办理；区分当前订单状态与包裹运输，明确不能让礼貌前后缀覆盖主诉。没有将测评集整句作为模型示例或召回词典。
3. **混合检索**：正文/标题 BM25F（标题权重 2），中文二元字组与英文/数字 token，少量通用业务同义词扩展；扩大向量候选池后使用 RRF，词法/向量权重 0.8/0.2、常数 10。按标题对重复 chunk 降权。没有硬编码“问题 → 相关标题”的映射。
4. **索引与回退**：Chroma 仍是权威数据源，词法索引只缓存快照，本实例写入后立即失效，其他进程写入在 30 秒内刷新。无词法命中时使用向量结果；空库和不足 K 条时安全返回。`KNOWLEDGE_RETRIEVAL_MODE=dense|sparse|hybrid` 可选择消融/回退模式，默认 `hybrid`，Compose 已透传该设置。

| 消融 | Accuracy | Macro-F1 |
|---|---:|---:|
| 原规则，不调用模型 | 38.80% | 0.4363 |
| 最终规则，不调用模型 | 60.80% | 0.6374 |
| 原完整分类链路 | 88.00% | 0.8801 |
| 最终规则 + 完整类别提示 + 原 Embedding/LLM | 95.20% | 0.9520 |

| 检索消融 | Hit@1 | Hit@5 | Recall@5 | 全部相关@5 |
|---|---:|---:|---:|---:|
| 纯向量 | 42.50% | 81.67% | 70.28% | 59.17% |
| 纯 BM25 | 95.00% | 100.00% | 97.50% | 95.00% |
| 混合 RRF（默认） | 95.83% | 100.00% | 96.67% | 93.33% |

纯 BM25 在这批题目上的 Top-5 覆盖略优；默认保留混合检索，以获得更好的 Top-1 和无词法命中时的语义召回。不能宣称混合方案在所有指标上都优于 BM25。没有单独测量规则与提示词的全部交互效应。

第一版候选的 Accuracy 仅 89%，并让部分账户资料问题落入通用 query/request；已保留 `candidate-v1/`，没有采用。补全领域边界的第二版达到 95.2%；之后补齐一般扣费规则、收紧主管请求匹配，再跑最终版本，Accuracy 同为 95.2%。中间候选不是同一配置的三次重复运行，不能当成稳定性证明。

## 证据与复现

- `comparison.json`：配对结果、回退样本、消融、边界集、Top-5 剩余未命中标题。
- `before/` 与 `after/`：完整报告和全部 500 条分类预测；检索报告保存每个 K 的逐题结果。
- `before-rules/`、`after-rules/`：纯规则消融；`sparse-rag/`：纯 BM25；`dense-rag/`：最终代码下切回纯向量，对原检索基线的再次确认。
- `before-boundary/`、`after-boundary/`、`dense-rag-boundary/`、`hybrid-rag-boundary/`：新增边界集结果。
- `candidate-v1*`、`candidate-v2*`、`hybrid-rag/`：保留的中间实验。

原意图/知识库实现的 SHA256 与 Git `c8e4d19231670fbbca149f498dabcc6fd26dc869` 对应文件相同。原问题文件、历史报告和历史预测未修改。报告记录数据 SHA256、实现 SHA256、模型和配置；最终 dense/hybrid 的知识库内容 SHA256 相同：`22279ae12a1c90bdd0054bddd6a84e84974922e5e6b72c1834dbad43cfb95000`。

在项目根目录准备运行环境（本次本地 Python 为 3.12.14、Chroma 0.5.23、NumPy 1.26.4）：

```bash
uv pip install --python python-service/.venv/bin/python \
  -r python-service/requirements.txt -r python-service/requirements-test.txt 'numpy<2'
```

终端一启动独立测评知识库，只公开只读测评接口；请为新实验选择独立目录：

```bash
PYTHONPATH=python-service python-service/.venv/bin/python \
  -m evaluation.optimization_experiment serve \
  --chroma-path /tmp/lumenmind-my-experiment-chroma \
  --port 8100 --retrieval-mode hybrid
```

终端二启动当前 Pi 服务，配置仍从项目 `.env` 读取：

```bash
cd agent-service
PI_HOST=127.0.0.1 PI_PORT=3100 \
  PYTHON_INFRA_URL=http://127.0.0.1:8100 \
  node --import tsx src/server.ts
```

终端三在项目根目录执行。`--output-dir` 必须是不存在的新目录，防止覆盖历史；完整分类链路会消耗模型额度：

```bash
PYTHONPATH=python-service python-service/.venv/bin/python \
  -m evaluation.optimization_experiment measure \
  --label my-experiment --output-dir data/eval/experiments/my-experiment
```

`--rules-only --intent-only` 测纯规则；`--retrieval-only` 只测检索。使用 `--intent-dataset`、`--retrieval-dataset` 可指定新的 JSONL。检索消融在启动 fixture 时选择 `--retrieval-mode dense` 或 `sparse`，然后使用新的输出目录测量。重现旧分类器应在上述 Git 版本的独立 checkout 中使用同一测评入口，不要覆盖当前工作区的实现。

## 验证与边界

- TypeScript：类型检查、构建及 185 项测试通过，包括原有复合问题主辅路由和新增边界回归。
- Python：264 项测试通过，包括空库/小库、候选扩展、索引写入失效、多标题覆盖、无词法命中回退、部分 Recall 错例报告。
- Python 编译检查、Compose 配置检查、现有核心测评集 `run_suite --dry-run`（20 个意图、30 个对话、重复参数 3）通过。dry-run 仅验证用例契约，没有执行完整对话/Judge 发布门禁。
- 原 120 题检索仍有 8 条未找齐全部相关标题，详见 `comparison.json`；跨文档背景标签和语义改写仍有改进空间。
- 固定样本被用于开发；12 篇短文档、Top-5 标题覆盖存在明显小语料优势。单次新基线/最终分类结果不能证明真实流量泛化或模型长期稳定性。词法索引会遍历语料，在大库上还需要专用检索服务与性能验收。
- 本次没有重跑生成答案与 LLM-as-Judge，不能把检索提升等同于答案质量提升；没有更新发布基线。
